## 六、Banner 品牌名 Patch 的实际定位过程

### 6.1 问题背景

启动时显示的 banner：

```
▗ ▗   ▖ ▖  Claude Code v2.1.126
           Opus 4.7 (1M context) · API Usage Billing
  ▘▘ ▝▝    /Users/chen
```

目标：把 `Claude Code` 改为 `Shadow Code`。

### 6.2 错误尝试

最初基于源码结构推测 banner 来自 `createElement(RW, {title:\`Claude Code v...\`})` 这一处，编写了 patch：

```javascript
pattern: /title:`Claude Code v\$\{/g,
replacer: () => 'title:`Shadow Code v${'
```

**结果**：patch 生效（cjs 中的 `title:` 确实被改为 `Shadow Code v`），但 banner 仍显示 `Claude Code`。

**原因**：offset 10245471 处的 `RW` 组件是另一个上下文的标题（可能是弹窗/对话框），**不是启动 banner**。

### 6.3 正确定位方法

通过 logo 字符 `▗`（Unicode `▗`）定位 banner 渲染位置：

```bash
node -e "
const code = require('fs').readFileSync('cli.original.cjs','utf8');
console.log(code.indexOf('▗'));  # → 7945580
"
```

从该位置向前追溯，找到消费 `tcH()` 返回数据的渲染组件（offset 10702606）：

```javascript
// banner 数据源
function tcH() {
  let H = `...VERSION:"2.1.126"...`;  // 纯版本号
  return { version: H, cwd, billingType, agentName };
}

// banner 渲染（关键！）
let {version: $, cwd: z, billingType: Y, agentName: w} = tcH();
// ...省略...
let a = E4.createElement(v, {bold:!0}, "Claude Code");  // ← 真正的 "Claude Code" 字符串
let TH = E4.createElement(v, null, a, " ", E4.createElement(v, {dimColor:!0}, "v", S));
```

**关键发现**：
- `tcH()` 只返回版本号，**不包含 "Claude Code" 文字**
- banner 标题中的 "Claude Code" 硬编码在渲染组件中，格式为 `createElement(v, {bold:!0}, "Claude Code")`

### 6.4 正则修正

| 错误正则 | 修正后 |
|---------|--------|
| `,bold:!0\},"Claude Code"\)` | `\{bold:!0\},"Claude Code"\)` |

原代码形如 `(v,{bold:!0},"Claude Code")`，前面是 `{` 不是 `,`。

### 6.5 最终 Patch

```javascript
{
  name: 'Banner: Claude Code → Shadow Code (bold text)',
  pattern: /\{bold:!0\},"Claude Code"\)/g,
  replacer: () => '{bold:!0},"Shadow Code")',
  sentinel: '{bold:!0},"Claude Code"',
}
```

### 6.6 经验教训

1. **源码结构推测不可靠**：`src/components/banner.tsx` 里看到的 JSX 在 minify 后可能散布在多个位置，一个 "Claude Code" 字符串可能对应多个渲染点（对话框、banner、错误消息等）。
2. **用 Unicode 字符做锚点**：logo 字符 `▗` 在整个代码中唯一出现在 banner 渲染处，是最可靠的定位手段。
3. **验证 patch 实际显示**：`grep -c` 能验证字符串被替换，但**不能验证 UI 是否使用被替换的位置**。必须启动程序看实际 banner 才能确认。
4. **追踪数据流比匹配字符串可靠**：从 `tcH()` 数据源往下追渲染组件，比在 13MB 的 minified 代码中搜关键字高效。

## 七、配套工具链位置确认

### 7.1 ShadowCode 安装目录结构

```
~/.shadowcode/
  ├── cli.original.cjs       patch 后的主代码（13MB）
  ├── cli.original.cjs.bak   patch 前备份
  ├── cli.cjs                Wrapper，注入配置

```

### 7.2 与官方 ~/.claude/ 目录的区别

| 目录 | 创建者 | 作用 | 卸载影响 |
|------|--------|------|---------|
| `~/.claude/` | Claude Code 官方 | 会话历史、todo、settings | ShadowCode 不会清理 |
| `~/.shadowcode/` | install-custom.sh | patch 后的程序本体 + 配置 | `--uninstall` 全部清理 |

两者独立，运行 `claude`（不管是原版还是 patch 版）都读写 `~/.claude/`。
